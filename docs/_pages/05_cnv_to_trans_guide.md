# 1. Overview
## 1.1. Target Services and Purpose of This Document
This document provides guidance for advertisers currently using NAVER Search Ad (SA) Premium Log Analysis or NAVER Performance Display Ad (GFA) conversion tracking services who want to change the script installed on their site from the old script (cnv version) to the new script (trans version).

This guide targets `independent malls`, meaning sites where the advertiser can freely modify the site's source code.

For `hosted malls (Cafe24, MakeShop, etc.)`, see the following 2 guides.<br>
 . [Hosted Mall Setup Guide for NAVER Ads Web Conversion Tracking]({{"/pages/02_ecom_platform_guide/"| relative_url}})<br>
 . [Manual Installation Guide for the New Hosted Mall Script (trans version) for NAVER Ads Web Conversion Tracking]({{"/pages/03_ecom_platform_trans_guide/"| relative_url}})<br>

## 1.2. Precautions When Installing and Testing

> ##### WARNING
> When testing script installation, make sure you understand the duplicate-conversion filtering logic below before testing.
When a conversion generated by the new script (trans) occurs, old-script (cnv) conversions treated as the same conversion type are permanently filtered. Please be careful when installation testing and make sure you understand the details below.
{: .block-warning }

The NAVER ad platforms (Search Ad and Performance Display Ad) currently apply duplicate-conversion filtering logic to prevent duplicate conversion values from being counted in ad reports due to duplicate conversion logs.<br>
The duplicate-conversion filtering logic is as follows.<br>
 . If a conversion generated by the new script occurs for a conversion type treated as the same type for a specific site identifier (NAVER common key, na_account_id), conversions generated by the old script (cnv) for that type are permanently filtered.<br>

For example<br>
 . A site with NAVER common key `s_123` was using conversion type `No. 3` add to cart in the old script (cnv) version.<br>
 . If an `add_to_cart` log, which is the add-to-cart conversion in the new script (trans) version, occurs even once on that site, then from that point onward, conversion type `No. 3` add to cart from the old script (cnv) version is permanently filtered. (Please note that there is no way to restore old-script (cnv) version logs so they are reflected in reports again.)<br>

The conversion type numbers in the old script (cnv) version and the conversion types in the new script (trans) version are mapped as follows.

![05_01_02-01]({{"/assets/img/05_01_02-01.png"| relative_url}})

As in the add-to-cart example above, if a `lead` conversion occurs in the new script (trans) version, conversion `No. 4` in the old script (cnv) version is permanently filtered.

If you are testing installation of the new script (trans), old-script (cnv) conversions may be filtered when the filtering logic above applies.<br>
 . Therefore, when entering the conversion type string for the new script (trans) version (for example, the `OOOOOO` part of `_conv.type = "OOOOOO";`), we recommend adding `test_` in front of the conversion type string you want to use (for example, if you are testing `add_to_cart`, set it to `test_add_to_cart`). This can prevent the unwanted situation where, while testing `add_to_cart`, existing conversion No. 3 (add to cart) generated by the old script (cnv) is permanently filtered.<br>
 We recommend entering the original conversion type string from the specification only after you have finished testing and confirmed that there are no issues.<br>
 
※ Note<br>
  . When testing with the new script (trans) version, you can use a string other than `purchase`, `sign_up`, `add_to_cart`, `lead`, and `custom001`, which have mappings between the old script (cnv) version and the new script (trans) version, when entering the conversion type string (for example, the `OOOOOO` part of `_conv.type = "OOOOOO";`).<br>
 . You can also test with a string that does not exist in the official documentation (for example, `test_conversion`). <br>
 . However, to prevent possible mistakes and for convenience, we recommend using the format `test_OOOOOO` in front of the conversion type string you want to use.<br>


# 2. New Script (trans version) Conversion Method Guide
## 2.0. Code Block Definitions
To help with explanation and understanding, the names of each code block are defined below.

### 2.0.1. Code Blocks in the Old Script (cnv version)

#### (1) Code block `C1`: Conversion value setup block
```html
<script type="text/javascript" src="//wcs.naver.net/wcslog.js"></script>

// Set conversion values using the conversion script
<script type="text/javascript">
    var _nasa={};
    if (window.wcs) _nasa["cnv"] = wcs.cnv("1","payment amount variable");
</script>
```

#### (2) Code block `C2`: Conversion-tracking cookie setup and PV generation block (when a conversion value is set, send the conversion value together with 1 PV log)
```html
// Send the conversion value set through the above script and the log for this page to the server

<script type="text/javascript" src="//wcs.naver.net/wcslog.js"></script>

<script type="text/javascript">
    if (!wcs_add) 
        var wcs_add = {};
    wcs_add["wa"] = "AccountId";    // Site identifier (= NAVER common key, na_account_id). Change appropriately for each site.

    if (!_nasa)
        var _nasa = {};
    if (window.wcs) {
        wcs.inflow("site-domain"); // Conversion-tracking cookie domain.
        wcs_do(_nasa); // Send log to the server
    }
</script>
```

### 2.0.2. Code Blocks in the New Script (trans version)

#### (1) Code block `T1`: Conversion-tracking cookie setup and PV generation block

```html
<script type="text/javascript" src="//wcs.naver.net/wcslog.js"></script>
 
<script type="text/javascript">
 
if (window.wcs) {
    if(!wcs_add) var wcs_add = {};

    // (2) Set the identifier for each site
    wcs_add["wa"] = "AccountId";     // Site identifier (= NAVER common key, na_account_id)
  
    // (3) Set the cookie domain for ad conversion tracking
    wcs.inflow("site-domain");

    // (4) Send the PV event
    wcs_do(); // Send the PV event
 }
 
</script>
```

#### (2) Code block `T2-1`: Simple conversion without (conversion) items
```html
<script type="text/javascript" src="//wcs.naver.net/wcslog.js"></script>

<script type="text/javascript">
 
 if (window.wcs) {
     if(!wcs_add) var wcs_add = {};
     
    // (2) Set the identifier for each site
    wcs_add["wa"] = "AccountId";     // Site identifier (= NAVER common key, na_account_id)
 
    // (5) Send the purchase-completion conversion event
    var _conv = {}; // Create an object to hold event information
   
    _conv.type = 'sign_up';  // Set the sign-up (sign_up) event on the object

    wcs.trans(_conv); // Send the object containing conversion event information to the server
  }
 
</script>
```


#### (3) Code block `T2-2`: (Conversion) purchase completion (purchase) conversion

```html
<script type="text/javascript" src="//wcs.naver.net/wcslog.js"></script>

<script type="text/javascript">
 
 if (window.wcs) {
     if(!wcs_add) var wcs_add = {};
     
    // (2) Set the identifier for each site
    wcs_add["wa"] = "AccountId";     // Site identifier (= NAVER common key, na_account_id)
 
    // (5) Send the purchase-completion conversion event
    var _conv = {}; // Create an object to hold event information
   
    _conv.type = 'purchase';  // Set the purchase (purchase) event on the object
    
    _conv.items = [       // Describe information about the content and target of the conversion event action
          { // item #1
            id: '8321',                   // string product id (required). If using NDA ads, it must match the product ID sent to the NAVER Shopping product EP.
            name: 'NAVER Sneakers83',     // string product name (required)
            quantity: 1,                  // number payment quantity (required)
            payAmount: 30000,             // number payment amount (required) (warning: this is the total amount for that product, not the unit price)
          },              
          { // item #2
            id: '9456'                    // string product id (required). If using NDA ads, it must match the product ID sent to the NAVER Shopping product EP.
            name: 'NAVER T-Shirt XL',     // string product name (required)
            quantity: 2,                  // number payment quantity (required)
            payAmount: 60000,             // number payment amount (required) (warning: this is the total amount for that product, not the unit price)
          }
    ];      
    
    _conv.value = '90000';     // Sum of payment amounts (payAmount) by item       
	
    wcs.trans(_conv); // Send the object containing conversion event information to the server
  }
 
</script>
```

## 2.1. Script Replacement Method

### STEP 01. Replace scripts by code block

![05_02_01-01]({{"/assets/img/05_02_01-01.png"| relative_url}})

On a conversion page, generally:

For the old script (cnv version)<br>
 . code block `C1` runs first,<br>
 . then code block `C2` runs.<br>

When changing to the new script (trans version)<br>
 . Delete code block `C1` (or comment it out so it does not run).<br>
 . Replace code block `C2` with code block `T1`.<br>
 . Insert a conversion script such as code block `T2-1` (or `T2-2`) below it. <br>
 (Or implement it so JavaScript runs in the order above.)<br>

If you want a conversion event to occur when a specific button on the site is clicked,
run code block `T1` when the page containing the button loads, 
and run code block `T2-1` (or code block `T2-2`) when the button click event occurs.

※ Warning<br>
 . If T2 runs first and T1 runs afterward, conversion tracking problems can occur. Make sure T2 runs after T1.

### STEP 02. Configure the parts of each code block that must be set separately for each site

When replacing code blocks, code blocks `T1` and `T2` require `(a) identifier for each site` and `(b) cookie domain for ad conversion tracking` settings below.
If there is no problem with the values you have been using, copy and use the same values.
```js
// (a) Set the identifier for each site
    wcs_add["wa"] = "AccountId";     // Site identifier (= NAVER common key, na_account_id)

// (b) Set the cookie domain for ad conversion tracking
  wcs.inflow("site-domain");
```

### STEP 03. Test
Visit the actual site, perform the conversion action, and check whether PV and conversion logs occur. 
For the test method, see the guide at {{"/pages/04_trans_script_test_guide/"| relative_url}}.

Make sure to review `1.2. Precautions When Installing and Testing`. When testing, we recommend adding the `test_` prefix in front of the conversion type you want to use, and then removing the `test_` prefix when you finally apply it.

If you have completed installation of the new script (trans version) on an (independent mall) site, we recommend contacting NHN Data, the official outsourced vendor for NAVER web conversion tracking script installation, and requesting a re-review to confirm that conversions are installed correctly. If you request a re-review, they will check whether the conversion script is installed correctly and provide the results. If anything is incorrect, they will let you know.
